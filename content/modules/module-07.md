## จุดประสงค์การสอน

- **7.1 เข้าใจหลักการสื่อสารแบบอนุกรมและความแตกต่างของ RS-232 กับ RS-485 ได้**
    - 7.1.1 จำแนกหลักการทำงานและความแตกต่างระหว่าง RS-232 และ RS-485 ได้
    - 7.1.2 ยกตัวอย่างการเชื่อมต่อ PLC กับอุปกรณ์ภายนอกผ่าน พอร์ต RS-232 และ RS-485 ได้
- **7.2 เข้าใจหลักการของโปรโตคอล Modbus และระบบ V-net IoT ได้**
    - 7.2.1 บอกหลักการของ Modbus RTU และ Modbus TCP ได้
    - 7.2.2 อธิบายแนวคิดของระบบ V-net IoT และการนำมาใช้ในระบบอัตโนมัติได้
    - 7.2.3 ยกตัวอย่างการส่งข้อมูลจาก PLC ไปยังระบบ IoT ผ่าน V-net ได้
- **7.3 ปฏิบัติการสื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอกได้ ถูกต้อง**
    - 7.3.1 สังเกตการตั้งค่าและสื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอกผ่านพอร์ต RS-232, RS-485 และ Modbus ได้ถูกต้อง
    - 7.3.2 ควบคุมความเสี่ยงด้านความปลอดภัยของข้อมูลเมื่อเชื่อม ต่อ Cloud ได้

ในระบบอัตโนมัติ (Automation System) การสื่อสารข้อมูลของ PLC (Programmable Logic Controller) มีบทบาทสำคัญในการเชื่อมโยงระหว่างหน่วยควบคุมหลักกับอุปกรณ์อื่นในกระบวนการผลิต เช่น เซนเซอร์ (Sensors), มอเตอร์ (Motors), อินเวอร์เตอร์ (Inverters), HMI (Human Machine Interface) และระบบคอมพิวเตอร์ควบคุมส่วนกลาง การเชื่อมโยงเหล่านี้ช่วยให้ระบบสามารถตรวจสอบ รับส่งคำสั่ง และแลกเปลี่ยนข้อมูลได้แบบเรียลไทม์ (Real-time Communication) ซึ่งเป็นหัวใจหลักของระบบ Automation ในโรงงานอัจฉริยะ (Smart Factory)

การสื่อสารข้อมูลของ PLC สามารถแบ่งได้เป็น 2 ประเภทหลัก ได้แก่ การสื่อสารแบบอนุกรม (Serial Communication) เช่น RS-232 และ RS-485 ซึ่งนิยมใช้ในงานที่มีอุปกรณ์จำนวนน้อย หรือการเชื่อมต่อระหว่าง PLC กับอุปกรณ์เฉพาะจุด เช่น HMI หรืออินเวอร์เตอร์ และการสื่อสารแบบเครือข่าย (Network Communication) เช่น Modbus TCP/IP และ V-net IoT ซึ่งรองรับการเชื่อมต่อหลายอุปกรณ์พร้อมกัน และสามารถส่งข้อมูลผ่านเครือข่าย Ethernet หรือ Internet ได้

## 7.1 หลักการสื่อสารแบบอนุกรมและความแตกต่างของ RS-232 กับ RS-485

### 7.1.1 หลักการทำงานและความแตกต่างระหว่าง RS-232 และ RS-485

การสื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอก เช่น คอมพิวเตอร์ HMI หรือเครื่องจักรอัตโนมัติอื่น ๆ จำเป็นต้องใช้พอร์ตสื่อสารมาตรฐานที่รองรับอุตสาหกรรม โดยเฉพาะ RS-232 และ RS-485 ซึ่งเป็นรูปแบบการสื่อสารอนุกรม (Serial Communication) ที่นิยมใช้ในงานอุตสาหกรรม เพราะมีความทนทานและเหมาะกับระยะทางและลักษณะงานที่แตกต่างกัน

ตารางที่ 7.1 การเปรียบเทียบ RS232 กับ RS-485

| รายการเปรียบเทียบ      | RS-232               | RS-485                         |
|----------------------|----------------------|--------------------------------|
| ลักษณะการสื่อสาร        | Point to Point       | Multi Drop                     |
| จำนวนอุปกรณ์สูงสุด       | 2 ตัว                 | 32 ตัว                          |
| ระยะทางสูงสุด          | 15 เมตร              | 1,200 เมตร                     |
| สัญญาณไฟฟ้า            | ±3V ถึง ±15V          | Differential ±2V ถึง ±6V        |
| ความต้านทานสัญญาณรบกวน | ต่ำ                   | สูง                             |
| การใช้งานทั่วไป         | เชื่อมต่อคอมพิวเตอร์, HMI | ระบบเครือข่ายอุตสาหกรรม, PLC Link |

RS-232 เหมาะสำหรับการสื่อสารระยะใกล้ระหว่างอุปกรณ์ 2 ตัว ในขณะที่ RS-485 เหมาะกับระบบเครือข่ายอุตสาหกรรมที่ต้องเชื่อมต่อหลายอุปกรณ์ในระยะไกล การเข้าใจหลักการและการต่อวงจรอย่างถูกต้องจะช่วยให้การสื่อสารข้อมูลระหว่าง PLC และอุปกรณ์อื่น ๆ มีความเสถียรและแม่นยำ

### 7.1.2 ตัวอย่างการเชื่อมต่อ PLC กับอุปกรณ์ภายนอกผ่านพอร์ต RS-232 และ RS-485

![](/images/book/image109.jpg)

ภาพที่ 7.1 โครงสร้างการเชื่อมต่อระบบสื่อสาร RS-232 และ RS-485

ภาพนี้แสดงการเชื่อมต่อและเปรียบเทียบการทำงานของระบบสื่อสาร RS-232 และ RS-485 ซึ่งเป็นมาตรฐานการสื่อสารอนุกรม (Serial Communication) ที่นิยมใช้ในงานควบคุมอัตโนมัติและระบบ PLC อุตสาหกรรม โดย RS-232 ใช้รูปแบบการเชื่อมต่อแบบ Point-to-Point (1 ต่อ 1) เช่น การเชื่อมต่อระหว่าง คอมพิวเตอร์กับ PLC ผ่านสายสื่อสารที่ประกอบด้วยขา TX (Transmit), RX (Receive) และ GND (Ground) เหมาะสำหรับการสื่อสารระยะสั้นไม่เกิน 15 เมตร และรองรับอุปกรณ์เพียงคู่เดียวในแต่ละการเชื่อมต่อส่วน RS-485 ใช้รูปแบบการเชื่อมต่อแบบ Multi-Drop Bus (1 ต่อหลายอุปกรณ์) โดยสามารถเชื่อมต่อ PLC หนึ่งเครื่องกับอุปกรณ์ Slave หลายตัว เช่น HMI, Sensor หรือ Inverter ได้ในสายสื่อสารเส้นเดียว ใช้คู่สาย A(+) และ B(-) สำหรับส่งสัญญาณแบบต่างเฟส (Differential Signal) ซึ่งช่วยลดสัญญาณรบกวนและสามารถส่งข้อมูลได้ไกลถึง 1,200 เมตร เหมาะกับงานอุตสาหกรรมที่ต้องการสื่อสารหลายอุปกรณ์พร้อมกัน

ตัวอย่างการเชื่อมต่อแบบ RS-232 ได้แก่ การต่อ PLC กับเครื่องอ่านบาร์โค้ด เครื่องพิมพ์ฉลาก หรือคอมพิวเตอร์ ในลักษณะจุดต่อจุด (Point-to-Point) ระยะไม่เกินประมาณ 15 เมตร โดยต่อสาย TxD ของอุปกรณ์หนึ่งเข้ากับ RxD ของอีกอุปกรณ์หนึ่งและต่อสาย GND ร่วมกัน ส่วนการเชื่อมต่อแบบ RS-485 นิยมใช้ต่อ PLC กับอุปกรณ์หลายตัวบนสายคู่ตีเกลียวเส้นเดียว เช่น Inverter มิเตอร์วัดพลังงาน หรือเครื่องควบคุมอุณหภูมิ ได้ระยะไกลถึงประมาณ 1,200 เมตร โดยต่อขา A(+) และ B(–) ของทุกอุปกรณ์แบบขนานกัน กำหนดหมายเลขสถานี (Station No.) ไม่ให้ซ้ำกัน และติดตั้งตัวต้านทานปลายสาย (Terminating Resistor) ประมาณ 120 โอห์มที่ปลายสายทั้งสองด้าน

## 7.2 โปรโตคอล Modbus และระบบ V-net IoT

### 7.2.1 หลักการของ Modbus RTU และ Modbus TCP

ในระบบอัตโนมัติอุตสาหกรรม (Industrial Automation System) การแลกเปลี่ยนข้อมูลระหว่างอุปกรณ์ต่าง ๆ เช่น PLC, HMI, Inverter, Sensor, และ Controller ถือเป็นหัวใจสำคัญของการควบคุมและตรวจสอบกระบวนการผลิตให้ทำงานอย่างมีประสิทธิภาพ หนึ่งในมาตรฐานการสื่อสารที่ได้รับความนิยมสูงสุดทั่วโลกคือ Modbus Protocol

Modbus ถูกพัฒนาโดยบริษัท Modicon (ปัจจุบันคือ Schneider Electric) ตั้งแต่ปี ค.ศ. 1979 เพื่อเป็นมาตรฐานเปิด (Open Protocol) ที่ช่วยให้อุปกรณ์จากผู้ผลิตต่าง ๆ สามารถสื่อสารและทำงานร่วมกันได้อย่างง่ายดาย โดยไม่จำเป็นต้องใช้โปรโตคอลเฉพาะยี่ห้อใดยี่ห้อหนึ่ง ปัจจุบัน Modbus จึงถูกใช้แพร่หลายทั้งในระบบ PLC, SCADA, BMS (Building Management System) และ Smart Factory

Modbus เป็นโปรโตคอลที่มีโครงสร้างเรียบง่าย ใช้หลักการ Master–Slave หรือ Client–Server ซึ่งหมายความว่าอุปกรณ์หลัก (Master) เช่น PLC จะเป็นผู้ร้องขอข้อมูล (Request) และอุปกรณ์ปลายทาง (Slave) เช่น HMI หรือ Sensor จะเป็นผู้ตอบกลับ (Response) ตามคำสั่งของ Master การออกแบบในลักษณะนี้ทำให้ Modbus มีความเสถียรและเหมาะสำหรับงานควบคุมในระดับอุตสาหกรรม

![](/images/book/image110.jpg)

ภาพที่ 7.2 โครงสร้างการเชื่อมต่อระบบ Modbus Protocol (RTU และ TCP)

ภาพแสดงการสื่อสารระหว่างอุปกรณ์ในระบบอัตโนมัติอุตสาหกรรมโดยใช้ Modbus Protocol ซึ่งประกอบด้วย PLC (Modbus Master) เชื่อมต่อกับอุปกรณ์ Slave หลายตัว เช่น Sensor, Motor Drive, Gateway และ HMI ผ่านทั้งสองรูปแบบการสื่อสาร ได้แก่ Modbus RTU ใช้สาย RS-485 เชื่อมต่อแบบอนุกรม และ Modbus TCP ใช้สาย Ethernet เชื่อมต่อแบบเครือข่าย

### 7.2.2 แนวคิดของระบบ V-net IoT และการนำมาใช้ในระบบอัตโนมัติ

ในยุคของ Industry 4.0 และการปฏิวัติอุตสาหกรรมดิจิทัล การสื่อสารข้อมูลระหว่างเครื่องจักรและระบบควบคุมไม่ได้จำกัดอยู่แค่ในระดับภายในโรงงานเท่านั้น แต่ยังขยายออกไปสู่การเชื่อมต่อกับระบบเครือข่ายและคลาวด์ (Cloud System) เพื่อให้สามารถจัดเก็บ วิเคราะห์ และควบคุมกระบวนการผลิตได้จากทุกที่ทุกเวลา หนึ่งในเทคโนโลยีที่ตอบโจทย์การสื่อสารลักษณะนี้คือ V-net IoT ซึ่งเป็นโซลูชันการสื่อสารข้อมูลอัจฉริยะจาก Mitsubishi Electric

V-net IoT (หรือ Virtual Network Internet of Things) เป็นระบบที่ช่วยให้ PLC, HMI, และอุปกรณ์อัตโนมัติอื่น ๆ สามารถเชื่อมต่อกับเครือข่ายอินเทอร์เน็ต เพื่อส่งข้อมูลแบบเรียลไทม์ไปยังระบบบริหารจัดการส่วนกลาง เช่น SCADA, Database Server, หรือ Cloud Platform ได้โดยตรง เทคโนโลยีนี้ช่วยให้ผู้ใช้งานสามารถติดตามสถานะเครื่องจักร วิเคราะห์ประสิทธิภาพการทำงาน (OEE – Overall Equipment Effectiveness) และตรวจจับความผิดปกติของกระบวนการผลิตได้จากระยะไกล

ระบบ V-net IoT ทำหน้าที่เป็นตัวกลางส่งข้อมูลจาก PLC ที่หน้างานขึ้นสู่ระบบคลาวด์ โดยอุปกรณ์เกตเวย์ (IoT Gateway) อ่านค่าจากหน่วยความจำของ PLC ผ่านพอร์ตสื่อสาร เช่น Ethernet หรือ RS-485 แล้วส่งข้อมูลผ่านเครือข่ายอินเทอร์เน็ตไปยังแพลตฟอร์มคลาวด์ ผู้ใช้สามารถติดตามสถานะเครื่องจักร ดูกราฟข้อมูลย้อนหลัง และรับการแจ้งเตือนผ่านคอมพิวเตอร์หรือโทรศัพท์มือถือได้จากทุกที่ การนำ V-net IoT มาใช้ในระบบอัตโนมัติจึงช่วยให้ทำการตรวจติดตามระยะไกล (Remote Monitoring) และการบำรุงรักษาเชิงคาดการณ์ได้ ซึ่งเป็นแนวคิดสำคัญของอุตสาหกรรม 4.0

ภาพที่ 7.3 โครงสร้างระบบการสื่อสาร V-net IoT

หน่วยเรียนนี้กล่าวถึงพื้นฐานและเทคโนโลยีการสื่อสารข้อมูลของ PLC (Programmable Logic Controller) ซึ่งเป็นหัวใจสำคัญของระบบควบคุมอัตโนมัติในอุตสาหกรรม โดยเนื้อหาครอบคลุมตั้งแต่การสื่อสารแบบอนุกรม โปรโตคอลมาตรฐาน ไปจนถึงการเชื่อมต่อกับระบบ IoT เพื่อรองรับโรงงานอัจฉริยะ (Smart Factory) เริ่มจาก RS-232 และ RS-485 ซึ่งเป็นรูปแบบการสื่อสารอนุกรม (Serial Communication) ที่นิยมใช้ในการแลกเปลี่ยนข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอก เช่น HMI, เซนเซอร์ หรืออินเวอร์เตอร์ โดย RS-232 เหมาะกับการเชื่อมต่อแบบจุดต่อจุด (Point-to-Point) ใช้ระยะสั้นไม่เกิน 15 เมตร ส่วน RS-485 รองรับการเชื่อมต่อแบบหลายจุด (Multi-Drop Bus) สามารถเชื่อมต่ออุปกรณ์หลายตัวในสายสื่อสารเดียว ส่งข้อมูลได้ไกลถึง 1,200 เมตร และมีความทนทานต่อสัญญาณรบกวนสูง จึงเหมาะกับระบบอุตสาหกรรมที่ต้องการความเสถียรในการสื่อสาร ต่อมาคือ Protocol Modbus ซึ่งเป็นมาตรฐานสื่อสารที่ใช้กันอย่างแพร่หลายเพื่อให้ PLC และอุปกรณ์อุตสาหกรรมยี่ห้อต่าง ๆ สามารถแลกเปลี่ยนข้อมูลกันได้ โดยมีทั้ง Modbus RTU ที่ใช้สื่อสารผ่าน RS-232/RS-485 และ Modbus TCP ที่ใช้ผ่านเครือข่าย Ethernet เพื่อการสื่อสารความเร็วสูง โครงสร้างเฟรมข้อมูลของ Modbus ประกอบด้วย Address, Function Code, Data และ CRC สำหรับตรวจสอบความถูกต้องของข้อมูล ช่วยให้ระบบทำงานได้อย่างมีประสิทธิภาพและเชื่อถือได้ สุดท้ายคือ V-net IoT ซึ่งเป็นเทคโนโลยีการสื่อสารสมัยใหม่ที่ผสานระบบควบคุมอุตสาหกรรมเข้ากับแนวคิด Internet of Things (IoT) โดยเชื่อมต่อข้อมูลจาก PLC ผ่าน Gateway ไปยัง Cloud เพื่อวิเคราะห์และแสดงผลแบบเรียลไทม์บน Dashboard ระบบนี้ช่วยให้ผู้ใช้งานสามารถตรวจสอบสถานะเครื่องจักร การผลิต หรือข้อมูลการบำรุงรักษาจากระยะไกลได้อย่างสะดวก เพิ่มประสิทธิภาพการบริหารจัดการ ลดการหยุดชะงัก และสนับสนุนการพัฒนาโรงงานอัจฉริยะอย่างยั่งยืน

## 7.3 สื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอก

หัวข้อนี้เป็นการฝึกปฏิบัติตามใบงานปฏิบัติหน่วยเรียนที่ 7 เรื่องสื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอก ใช้เวลา 3 ชั่วโมง (180 นาที) ผู้เรียนนำความรู้จากหัวข้อที่ผ่านมามาปฏิบัติงานจริงกับชุดฝึก และบันทึกผลลงในแบบบันทึกผลการปฏิบัติงาน โดยมีลำดับขั้นการปฏิบัติงานดังนี้

ขั้นที่ 1 รับชุดฝึก ตรวจความพร้อม และตรวจสอบการเชื่อมต่อทางกายภาพ (10 นาที)

ขั้นที่ 2 ตั้งค่าการสื่อสาร Ethernet ระหว่าง PLC กับ HMI และทดสอบการรับ-ส่งข้อมูล (30 นาที)

ขั้นที่ 3 ต่อสาย RS-485 และตั้งค่า Baud rate, Parity, Stop bit และหมายเลข Station ของ PLC ให้ตรงกับอุปกรณ์ Slave (40 นาที)

ขั้นที่ 4 เขียนโปรแกรมอ่านและเขียนค่ารีจิสเตอร์ของอุปกรณ์ Slave ด้วย MODBUS-RTU แล้วตรวจสอบค่าที่ได้ (40 นาที)

ขั้นที่ 5 ตั้งค่า V-Box เชื่อมต่อกับ PLC และลงทะเบียนอุปกรณ์เข้าสู่ระบบ Cloud (30 นาที)

ขั้นที่ 6 เรียกดูและสั่งงานข้อมูลของ PLC แบบเรียลไทม์ผ่านสมาร์ตโฟน (20 นาที)

ขั้นที่ 7 สรุปผล ส่งแบบบันทึกผล และเก็บอุปกรณ์ (10 นาที)

### 7.3.1 งานสื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอกผ่านพอร์ต RS-232, RS-485 และ Modbus

เมื่อปฏิบัติงานในหัวข้อนี้แล้ว ผู้เรียนสามารถสังเกตการตั้งค่าและสื่อสารข้อมูลระหว่าง PLC กับอุปกรณ์ภายนอกผ่านพอร์ต RS-232, RS-485 และ Modbus ได้ถูกต้อง โดยปฏิบัติตามลำดับขั้นในใบงานปฏิบัติหน่วยเรียนที่ 7 และให้ครูผู้สอนตรวจสอบก่อนจ่ายไฟหรือสั่งงานระบบทุกครั้ง

### 7.3.2 งานความเสี่ยงด้านความปลอดภัยของข้อมูลเมื่อ เชื่อมต่อ Cloud

เมื่อปฏิบัติงานในหัวข้อนี้แล้ว ผู้เรียนสามารถควบคุมความเสี่ยงด้านความปลอดภัยของข้อมูลเมื่อเชื่อม ต่อ Cloud ได้ โดยปฏิบัติตามลำดับขั้นในใบงานปฏิบัติหน่วยเรียนที่ 7 และให้ครูผู้สอนตรวจสอบก่อนจ่ายไฟหรือสั่งงานระบบทุกครั้ง

## บทสรุป

การสื่อสารระหว่าง PLC กับอุปกรณ์อื่นทำได้หลายรูปแบบ เช่น Ethernet, RS-232 และ RS-485 โดย RS-485 รองรับการเชื่อมต่อหลายอุปกรณ์และระยะทางไกลกว่า RS-232 โปรโตคอล MODBUS ใช้แลกเปลี่ยนข้อมูลระหว่าง Master และ Slave ผ่านรีจิสเตอร์ ส่วน V-net IoT ช่วยนำข้อมูลของ PLC ขึ้นสู่ระบบ Cloud เพื่อเฝ้าสังเกตผ่านอุปกรณ์เคลื่อนที่ ผู้ใช้ต้องตั้งค่าพารามิเตอร์ให้ตรงกัน และคำนึงถึงความปลอดภัยของข้อมูล

## แบบฝึกหัดท้ายหน่วยเรียน

คำชี้แจง: ให้นักศึกษาตอบคำถามต่อไปนี้โดยใช้ความรู้จากบทเรียน พร้อมยกตัวอย่างประกอบ หากสามารถอธิบายพร้อมวาดภาพวงจรหรือแผนผังการต่อสายได้จะได้รับคะแนนเพิ่ม

**1. อธิบายความสำคัญของการสื่อสารข้อมูลในระบบอัตโนมัติ (Automation System) และบทบาทของ PLC ในการเชื่อมโยงกับอุปกรณ์อื่น ๆ ในโรงงานอัจฉริยะ (Smart Factory)**

<details><summary>เฉลย</summary>

การสื่อสารข้อมูลในระบบ Automation มีความสำคัญในการเชื่อมโยงอุปกรณ์ต่าง ๆ เช่น Sensor, HMI, Inverter ให้ทำงานร่วมกันได้แบบเรียลไทม์ PLC ทำหน้าที่เป็นหน่วยควบคุมหลัก รับสัญญาณจากอุปกรณ์อินพุต ประมวลผลตามโปรแกรม และส่งคำสั่งไปยังอุปกรณ์เอาต์พุต ในโรงงานอัจฉริยะ (Smart Factory) PLC ยังเชื่อมต่อกับระบบ SCADA, HMI และ Cloud เพื่อให้ผู้จัดการสามารถตรวจสอบและควบคุมกระบวนการผลิตได้จากระยะไกล เพิ่มประสิทธิภาพและลดความสูญเสียในกระบวนการผลิต

</details>

**2. อธิบายหลักการทำงานของการสื่อสารแบบอนุกรม (Serial Communication) พร้อมเปรียบเทียบลักษณะการเชื่อมต่อของ RS-232 และ RS-485**

<details><summary>เฉลย</summary>

การสื่อสารแบบอนุกรม (Serial Communication) ส่งข้อมูลทีละ 1 บิตผ่านสายสัญญาณเดียว มีความเรียบง่ายและเหมาะกับงานอุตสาหกรรม

• RS-232 : ใช้สัญญาณ Single-ended เชื่อมต่อแบบ Point-to-Point (1:1) ระยะสั้นไม่เกิน 15 เมตร เหมาะกับการเชื่อมต่อ PLC กับคอมพิวเตอร์หรือ HMI แบบตัวต่อตัว

• RS-485 : ใช้สัญญาณ Differential (A+, B-) เชื่อมต่อแบบ Multi-Drop Bus ได้สูงสุด 32 อุปกรณ์ ระยะทางสูงสุด 1,200 เมตร ทนทานต่อสัญญาณรบกวนสูง เหมาะกับงานอุตสาหกรรมขนาดใหญ่

</details>

**3. จากตารางการเปรียบเทียบ RS-232 และ RS-485 จงอธิบายข้อดีและข้อจำกัดของแต่ละระบบ รวมถึงการเลือกใช้งานให้เหมาะสมกับลักษณะของงานอุตสาหกรรม**

<details><summary>เฉลย</summary>



</details>

**4. ให้นักศึกษาวาดแผนผังหรืออธิบายลำดับการเชื่อมต่อของ PLC กับอุปกรณ์ภายนอก ผ่านพอร์ต RS-232 และ RS-485 พร้อมอธิบายหน้าที่ของขา TX, RX, GND, A(+) และ B(-)**

<details><summary>เฉลย</summary>

RS-232 (Point-to-Point)

\[PLC TXD\] ──→ \[RXD คอมพิวเตอร์/HMI\]

\[PLC RXD\] ←── \[TXD คอมพิวเตอร์/HMI\]

\[GND\] ────── \[GND\]

TXD (Transmit Data) ส่งข้อมูลออกจาก PLC

RXD (Receive Data) รับข้อมูลเข้าสู่ PLC

GND (Ground) จุดอ้างอิงสัญญาณร่วม

RS-485 (Multi-Drop Bus)

\[PLC A(+)\] ──── Bus A(+) ──── \[Slave1 A+\] \[Slave2 A+\] ... \[SlaveN A+\]

\[PLC B(-)\] ──── Bus B(-) ──── \[Slave1 B-\] \[Slave2 B-\] ... \[SlaveN B-\]

A(+) : สายสัญญาณบวก (Non-Inverting)

B(-) : สายสัญญาณลบ (Inverting)

ควรต่อ Termination Resistor 120Ω ที่ปลายสายทั้งสองด้านเพื่อลดการสะท้อนสัญญาณ

</details>

**5. อธิบายหลักการสื่อสารของ Modbus Protocol ในรูปแบบ RTU และ TCP ว่ามีความแตกต่างกันอย่างไร และมีข้อดีอย่างไรในงานควบคุมอัตโนมัติ**

<details><summary>เฉลย</summary>

Modbus RTU ส่งข้อมูลในรูปแบบไบนารีผ่าน RS-232/RS-485 ใช้ CRC ตรวจสอบความถูกต้อง เหมาะกับงานอุตสาหกรรมที่มีอุปกรณ์อยู่ในพื้นที่เดียวกัน ความเร็วสูงสุด 115,200 bps

Modbus TCP ส่งข้อมูลผ่านเครือข่าย Ethernet (TCP/IP) รองรับความเร็วสูงกว่า เหมาะกับการเชื่อมต่อกับ SCADA, HMI หรือระบบจัดการส่วนกลางผ่านเครือข่าย ไม่จำกัดระยะทาง

</details>

**6. อธิบายโครงสร้างของเฟรมข้อมูล (Data Frame) ในระบบ Modbus พร้อมระบุหน้าที่ของส่วนประกอบหลัก เช่น Address, Function Code และ Data**

<details><summary>เฉลย</summary>

Modbus RTU Frame

Address ระบุหมายเลข Slave ที่ Master ต้องการสื่อสาร (0 = Broadcast)

Function Code กำหนดประเภทคำสั่ง เช่น 01=อ่าน Coil, 03=อ่าน Register, 06=เขียน Register

Data ข้อมูลตามชนิดของ Function Code เช่น ที่อยู่หน่วยความจำ จำนวนที่อ่าน หรือค่าที่เขียน

CRC ใช้ตรวจสอบว่าข้อมูลที่รับครบถ้วนและไม่มีข้อผิดพลาด

</details>

**7. ยกตัวอย่างการประยุกต์ใช้ Modbus RTU หรือ Modbus TCP ในระบบอุตสาหกรรมจริง เช่น การเชื่อมต่อ PLC กับ Inverter หรือ Sensor แล้วอธิบายการทำงานของระบบดังกล่าว**

<details><summary>เฉลย</summary>

ตัวอย่าง : การเชื่อมต่อ PLC (Modbus Master) กับ Inverter (Modbus Slave) ด้วย Modbus RTU ผ่าน RS-485

PLC (Master) ส่งคำสั่ง Function Code 06 (Write Single Register) ไปยัง Inverter เพื่อตั้งค่าความถี่มอเตอร์

Inverter (Slave) รับคำสั่งและตอบกลับยืนยันการรับข้อมูล

PLC ส่งคำสั่ง Function Code 03 (Read Holding Registers) เพื่ออ่านสถานะกระแสและแรงดันของมอเตอร์

ข้อมูลที่ได้ถูกนำไปแสดงผลบน HMI และบันทึกใน SCADA เพื่อวิเคราะห์ประสิทธิภาพ

</details>

**8. อธิบายแนวคิดของระบบ V-net IoT และบทบาทของเทคโนโลยีนี้ในการเชื่อมต่อ PLC เข้ากับระบบ Cloud เพื่อจัดเก็บและวิเคราะห์ข้อมูลการผลิต**

<details><summary>เฉลย</summary>

V-net IoT เป็นระบบที่เชื่อมต่อ PLC กับเครือข่ายอินเทอร์เน็ตผ่าน Gateway เพื่อส่งข้อมูลแบบเรียลไทม์ไปยัง Cloud Platform ทำให้สามารถวิเคราะห์ข้อมูลการผลิต ตรวจสอบสถานะเครื่องจักร และแจ้งเตือนความผิดปกติได้จากระยะไกลผ่าน Dashboard ตอบสนองแนวคิด Industry 4.0 และ Smart Factory

</details>

**9. จากโครงสร้างของ V-net IoT System ให้นักศึกษาอธิบายหน้าที่ของอุปกรณ์หลักแต่ละส่วน ได้แก่ PLC, V-net IoT Gateway, Cloud และ Dashboard พร้อมยกตัวอย่างการใช้งานในโรงงานจริง**

<details><summary>เฉลย</summary>

PLC เป็นแหล่งต้นทางข้อมูล รับสัญญาณจาก Sensor และควบคุมเครื่องจักรในพื้นที่โรงงาน ส่งข้อมูลสถานะให้ Gateway

V-net IoT Gateway ทำหน้าที่เป็นสะพานเชื่อมระหว่าง PLC และ Cloud แปลงโปรโตคอลการสื่อสาร เข้ารหัสข้อมูลและส่งผ่านอินเทอร์เน็ต

Cloud Platform รับและจัดเก็บข้อมูลจาก Gateway ประมวลผลด้วย AI หรืออัลกอริทึมวิเคราะห์ข้อมูล และส่งผลลัพธ์ไปยัง Dashboard

Dashboard แสดงผลข้อมูลในรูปแบบกราฟ แผนภูมิ หรือ Alarm ที่เข้าใจง่าย ผู้จัดการโรงงานสามารถตรวจสอบการผลิตได้จากสมาร์ตโฟนหรือคอมพิวเตอร์

</details>

**10. สรุปภาพรวมของการสื่อสารระหว่าง PLC กับอุปกรณ์อื่น ๆ ตั้งแต่ระดับ Serial Communication, Modbus Protocol จนถึง V-net IoT ว่ามีส่วนช่วยอย่างไรในการพัฒนาอุตสาหกรรมสมัยใหม่ให้เป็นระบบอัจฉริยะและมีประสิทธิภาพมากขึ้น**

<details><summary>เฉลย</summary>

การสื่อสารระหว่าง PLC กับอุปกรณ์อื่น ๆ สามารถมองเป็น 3 ระดับ ดังนี้

ระดับที่ 1 Serial Communication (RS-232/RS-485) : การสื่อสารพื้นฐานระหว่าง PLC กับอุปกรณ์ภายนอกในระยะใกล้หรือไกล เหมาะกับการเชื่อมต่ออุปกรณ์เฉพาะจุดหรือเครือข่ายขนาดเล็ก

ระดับที่ 2 Modbus Protocol (RTU/TCP) : มาตรฐานเปิดที่ช่วยให้อุปกรณ์จากผู้ผลิตต่าง ๆ สื่อสารกันได้ ลดต้นทุนและเพิ่มความยืดหยุ่นของระบบ เหมาะกับ SCADA และการควบคุมหลายอุปกรณ์

ระดับที่ 3 V-net IoT (Cloud/Internet) : การสื่อสารระดับสูงที่เชื่อมต่อระบบอุตสาหกรรมกับ Internet เพื่อวิเคราะห์ข้อมูลแบบ Big Data และพัฒนาโรงงานอัจฉริยะตามแนวคิด Industry 4.0

การผสานเทคโนโลยีทั้ง 3 ระดับเข้าด้วยกันทำให้ระบบอุตสาหกรรมมีความยืดหยุ่น ปลอดภัย และสามารถบริหารจัดการได้อย่างมีประสิทธิภาพ ตอบสนองความต้องการของการผลิตสมัยใหม่ได้อย่างครบถ้วน

</details>
