## จุดประสงค์การสอน

- **10.1 อธิบายเรื่องการค้นหาและแก้ไขข้อผิดพลาด**
    - 10.1.1 บอกความหมายและองค์ประกอบในเรื่องการค้นหาและแก้ไขข้อผิดพลาดได้ถูกต้อง
    - 10.1.2 อธิบายหลักการทำงานหรือวิธีใช้งานในเรื่องการค้นหาและแก้ไขข้อผิดพลาดได้ถูกต้อง
- **10.2 อธิบายเรื่องการป้องกันความเสียหาย**
    - 10.2.1 บอกความหมายและองค์ประกอบในเรื่องการป้องกันความเสียหายได้ถูกต้อง
    - 10.2.2 อธิบายหลักการทำงานหรือวิธีใช้งานในเรื่องการป้องกันความเสียหายได้ถูกต้อง
- **10.3 อธิบายเรื่องการบำรุงรักษา PLC**
    - 10.3.1 บอกความหมายและองค์ประกอบในเรื่องการบำรุงรักษา PLCได้ถูกต้อง
    - 10.3.2 อธิบายหลักการทำงานหรือวิธีใช้งานในเรื่องการบำรุงรักษา PLCได้ถูกต้อง

ในระบบควบคุมการทำงานของเครื่องจักรอัตโนมัติ PLC (Programmable Logic Controller) เป็นอุปกรณ์สำคัญที่ทำหน้าที่ประมวลผลและควบคุมการทำงานของอุปกรณ์ต่าง ๆ ภายในกระบวนการผลิต เพื่อให้ระบบทำงานได้อย่างมีประสิทธิภาพและต่อเนื่อง การบำรุงรักษาและตรวจสอบสภาพการทำงานของ PLC จึงเป็นสิ่งจำเป็นอย่างยิ่ง เพื่อป้องกันความเสียหาย ลดเวลาหยุดเครื่อง (Downtime) และยืดอายุการใช้งานของอุปกรณ์

ในหน่วยนี้ผู้เรียนจะได้ศึกษาวิธีการตรวจสอบและวิเคราะห์ข้อผิดพลาดของระบบ PLC ทั้งในส่วนของฮาร์ดแวร์และซอฟต์แวร์ เช่น การตรวจสอบไฟแสดงสถานะ (Indicator Lamp) การทดสอบ Input/Output การตรวจสอบโปรแกรมภายใน และการใช้เครื่องมือซอฟต์แวร์ช่วยวิเคราะห์ รวมถึงเรียนรู้แนวทางการบำรุงรักษาเชิงป้องกัน (Preventive Maintenance) เพื่อให้ระบบ PLC พร้อมใช้งานตลอดเวลาและลดความเสี่ยงจากความเสียหายที่อาจเกิดขึ้น

## 10.1 การค้นหาและแก้ไขข้อผิดพลาด

ระบบควบคุมเครื่องจักรอัตโนมัติที่ใช้ PLC (Programmable Logic Controller) เป็นศูนย์กลางการประมวลผล การทำงานผิดพลาดเพียงเล็กน้อยอาจส่งผลให้เครื่องจักรหยุดทำงานทั้งระบบ เกิดการสูญเสียเวลาในการผลิต (Downtime) และเพิ่มต้นทุนการซ่อมบำรุง ดังนั้นการเรียนรู้ การค้นหาและแก้ไขข้อผิดพลาด (Troubleshooting) จึงเป็นทักษะสำคัญของวิศวกรและช่างเทคนิค

การแก้ไขปัญหา PLC ไม่ได้เป็นเพียงการเปลี่ยนชิ้นส่วนหรือรีเซ็ตระบบเท่านั้น แต่ต้องอาศัยความเข้าใจเชิงลึกเกี่ยวกับวงจรไฟฟ้า การทำงานของโปรแกรมใน GX Works3 รวมถึงหลักการทำงานของอุปกรณ์ Input/Output ที่เชื่อมต่อกับ PLC ผู้เรียนจึงควรเรียนรู้วิธีวิเคราะห์หาสาเหตุอย่างเป็นระบบ และใช้เครื่องมือช่วยตรวจสอบอย่างถูกต้อง เพื่อให้การแก้ไขปัญหามีประสิทธิภาพและปลอดภัย

### 10.1.1 สาเหตุที่ทำให้ระบบ PLC ทำงานผิดพลาด

การทำงานผิดพลาดของระบบ PLC อาจเกิดขึ้นได้จากหลายสาเหตุ ทั้งด้าน ฮาร์ดแวร์ (Hardware) และ ซอฟต์แวร์ (Software) ดังนี้

1.  ปัญหาด้านฮาร์ดแวร์ (Hardware Fault)

สายไฟขาดหรือหลวม ทำให้สัญญาณไม่ถึง Input/Output

อุปกรณ์ตรวจจับ (Sensor) หรืออุปกรณ์ขับเคลื่อน (Actuator) เสียหาย

แหล่งจ่ายไฟ (Power Supply) มีแรงดันไม่คงที่

ความร้อนหรือความชื้นสูงเกินไป ทำให้วงจรอิเล็กทรอนิกส์ใน PLC เสื่อมสภาพ

2.  ปัญหาด้านซอฟต์แวร์ (Software Error)

โปรแกรม Ladder Diagram ถูกเขียนผิดลำดับตรรกะ (Logic Error)

ตั้งค่าพารามิเตอร์ของ I/O หรือโมดูลไม่ถูกต้อง

ความผิดพลาดในการสื่อสารระหว่าง PLC กับอุปกรณ์อื่น เช่น HMI หรือ Modbus

3.  ปัจจัยภายนอก (External Interference)

สัญญาณรบกวนทางไฟฟ้า (Electrical Noise) จากมอเตอร์หรืออินเวอร์เตอร์

การต่อสายกราวด์ไม่ถูกต้อง

การใช้สายสัญญาณที่ไม่มีการป้องกัน (Shield)

การระบุสาเหตุของความผิดพลาดเป็นขั้นตอนแรกที่สำคัญ เพราะช่วยลดเวลาในการซ่อมและป้องกันการแก้ไขผิดจุด

### 10.1.2 วิธีการตรวจสอบและแก้ไขข้อผิดพลาด

เมื่อเกิดปัญหากับระบบ PLC ควรดำเนินการตรวจสอบตามลำดับขั้นตอนอย่างเป็นระบบ ดังนี้

\(1\) ตรวจสอบสัญญาณไฟแสดงสถานะ (Indicator Lamp)

> ไฟ POWER แสดงสถานะการจ่ายไฟให้ PLC
>
> ไฟ RUN / STOP แสดงสถานะการทำงานของ CPU
>
> ไฟ ERROR / ALARM แสดงข้อผิดพลาด เช่น หน่วยความจำล้น หรือคำสั่งผิด

\(2\) ตรวจสอบ Input / Output

> ใช้โปรแกรม GX Works3 → Online → Monitor เพื่อตรวจสอบสถานะของแต่ละ Input (X) และ Output (Y)
>
> หากพบว่าสัญญาณ Input ไม่เปลี่ยนสถานะเมื่ออุปกรณ์ทำงาน อาจเกิดจาก Sensor เสียหรือสายสัญญาณขาด
>
> ถ้า Output ไม่ทำงาน ทั้งที่โปรแกรมสั่งแล้ว ควรตรวจสอบรีเลย์ โมดูลเอาต์พุต หรือภาคจ่ายไฟ

\(3\) ใช้เครื่องมือช่วยวิเคราะห์ (Diagnostic Tools)

> ใช้คำสั่ง Device Memory Monitor (D, M, X, Y) เพื่อตรวจสอบค่าที่เปลี่ยนแปลงระหว่างการทำงาน
>
> ใช้ฟังก์ชัน Error Log ตรวจดูรหัสข้อผิดพลาด (Error Code) ที่ CPU บันทึกไว้
>
> สำหรับระบบที่เชื่อมต่อผ่านเครือข่าย เช่น Modbus หรือ Ethernet สามารถใช้ฟังก์ชัน Communication Diagnostics เพื่อตรวจสอบแพ็กเก็ตข้อมูล

\(4\) ทดสอบการทำงานหลังแก้ไข

> เมื่อแก้ไขแล้วควรทดสอบด้วยโหมด Simulation Mode ก่อนรันจริง
>
> ตรวจสอบลำดับการทำงานและผลลัพธ์ว่าตรงตามที่ออกแบบหรือไม่

### 10.1.3 การตรวจสอบอย่างเป็นระบบ (Systematic Troubleshooting)

การตรวจสอบข้อผิดพลาดอย่างเป็นระบบเป็นแนวทางสำคัญในการวิเคราะห์ปัญหา โดยมีขั้นตอนดังนี้

1\. ระบุอาการเสีย (Symptom Identification)

สังเกตจากไฟแสดงสถานะ เสียงเตือน หรืออาการผิดปกติของอุปกรณ์

2\. วิเคราะห์สาเหตุที่เป็นไปได้ (Possible Cause Analysis)

เช่น สัญญาณไม่เข้า, รีเลย์ไม่ทำงาน, โปรแกรมหยุดทำงาน

3\. ตรวจสอบจุดที่สงสัย (Test and Verify)

ใช้มัลติมิเตอร์หรือซอฟต์แวร์ Monitor ตรวจสอบ Input/Output ที่เกี่ยวข้อง

4\. ดำเนินการแก้ไข (Corrective Action)

เปลี่ยนหรือซ่อมส่วนที่เสีย เช่น Sensor, สายไฟ, หรือแก้ไข Ladder

5\. บันทึกผลการซ่อม (Maintenance Log)

เพื่อใช้เป็นข้อมูลสำหรับการบำรุงรักษาในอนาคต

![ภาพที่ 10.1 การตรวจสอบสถานะการทำงานของ PLC ด้วย GX Works3 Monitor](/images/book/image142.jpg)

ภาพนี้แสดงหน้าต่างการตรวจสอบ (Monitor) ของโปรแกรม GX Works3 ซึ่งใช้สำหรับดูสถานะ Input (X0–X7) และ Output (Y0–Y7) แบบเรียลไทม์ในระหว่างการทำงานจริง ผู้ใช้สามารถดูการเปลี่ยนแปลงของบิตในขณะที่เครื่องจักรทำงาน เพื่อช่วยระบุว่าอุปกรณ์ใดไม่ตอบสนอง เช่น เซนเซอร์ไม่ส่งสัญญาณ หรือรีเลย์ไม่ทำงาน ภาพนี้เป็นเครื่องมือสำคัญในการวิเคราะห์ปัญหาเบื้องต้นของระบบ PLC

## 10.2 การป้องกันความเสียหาย

การป้องกันความเสียหายของอุปกรณ์ถือเป็นสิ่งสำคัญอย่างยิ่ง เพราะเมื่ออุปกรณ์ควบคุมได้รับความเสียหาย ไม่เพียงทำให้เครื่องจักรหยุดการทำงาน แต่ยังอาจก่อให้เกิดความเสียหายต่อกระบวนการผลิตทั้งหมด ดังนั้น ผู้เรียนจำเป็นต้องเข้าใจหลักการและแนวทางในการป้องกันปัจจัยที่อาจทำให้เกิดความเสียหาย เช่น ไฟกระชาก ความร้อน ความชื้น และสัญญาณรบกวนทางไฟฟ้า (Electrical Noise) เพื่อยืดอายุการใช้งานของอุปกรณ์ และรักษาความเสถียรของระบบโดยรวม

การป้องกันความเสียหายของ PLC ไม่ได้ขึ้นอยู่กับตัวอุปกรณ์เพียงอย่างเดียว แต่ยังรวมถึง การออกแบบระบบติดตั้งที่ถูกต้อง (Installation Design) การเดินสายไฟ การต่อกราวด์ที่เหมาะสม รวมถึงการบำรุงรักษาเชิงป้องกัน (Preventive Maintenance) อย่างสม่ำเสมอ การเข้าใจหลักการเหล่านี้จะช่วยให้ผู้ปฏิบัติงานสามารถออกแบบ ติดตั้ง และดูแลระบบให้มีความปลอดภัยและเสถียรสูงสุด โดยมีหลักการดังต่อไปนนี้

### 10.2.1 หลักการและวิธีการป้องกันความเสียหายของ PLC

1.  การป้องกันไฟกระชาก (Surge Protection)

ไฟกระชากหรือแรงดันไฟฟ้าสูงชั่วขณะอาจเกิดจากการเปิด–ปิดมอเตอร์ อินเวอร์เตอร์ หรือฟ้าผ่า ซึ่งสามารถทำให้วงจรภายใน PLC เสียหายได้ วิธีการป้องกันได้แก่

> ติดตั้ง Surge Protector (SPD) หรือ Varistor (MOV) ที่แหล่งจ่ายไฟ
>
> ใช้ Opto-isolator หรือ Relay Interface ระหว่างอุปกรณ์ภายนอกกับ PLC
>
> แยกสายไฟของโหลดกำลังสูง (เช่น มอเตอร์) ออกจากสายสัญญาณควบคุม

2.  การต่อกราวด์ที่ถูกต้อง (Proper Grounding)

การต่อกราวด์ช่วยลดสัญญาณรบกวนทางไฟฟ้าและป้องกันอันตรายจากไฟฟ้ารั่ว วิธีการต่อกราวด์ที่ดีมีหลักดังนี้

> ใช้สายกราวด์ขนาดไม่ต่ำกว่า 2.0 mm² และต่อเข้าจุดกราวด์กลางของตู้ควบคุม
>
> PLC, Power Supply, และ Shield Cable ต้องต่อกราวด์ร่วมกันที่จุดเดียว (Star Ground)
>
> ห้ามต่อกราวด์หลายจุด (Loop Ground) เพราะอาจเกิดแรงดันไหลวน (Ground Loop)

3.  การป้องกันความร้อน (Heat Protection)

ความร้อนสูงเกินไปทำให้วงจรอิเล็กทรอนิกส์ใน PLC เสื่อมสภาพและอาจทำให้ระบบหยุดทำงาน วิธีการป้องกัน ได้แก่

> ติดตั้ง PLC ในตู้ควบคุมที่มีพัดลมหรือพัดลมดูดอากาศ (Fan Filter Unit)
>
> จัดวางอุปกรณ์โดยเว้นช่องว่างระบายความร้อนตามคู่มือของผู้ผลิต (อย่างน้อย 50 mm รอบตัว PLC)
>
> หลีกเลี่ยงการติดตั้งใกล้แหล่งความร้อน เช่น หม้อแปลงหรืออินเวอร์เตอร์

4.  การป้องกันสัญญาณรบกวนทางไฟฟ้า (Noise Protection)

> ใช้สายสัญญาณแบบ Shield Cable สำหรับการต่ออุปกรณ์ตรวจจับ (Sensor)
>
> ใช้ Ferrite Core หรือ Noise Filter ในสายไฟของโหลดที่เป็นมอเตอร์หรือโซลินอยด์
>
> เดินสายสัญญาณแยกจากสายไฟแรงดันสูงอย่างน้อย 10 ซม.

### 10.2.2 การออกแบบระบบติดตั้ง PLC ที่ปลอดภัย

ตัวอย่างการออกแบบระบบติดตั้งที่ดีควรมีองค์ประกอบดังนี้

> แยกส่วนของ วงจรควบคุม (Control Circuit) และ วงจรกำลัง (Power Circuit) อย่างชัดเจน
>
> ใช้เบรกเกอร์แยกแต่ละส่วน เช่น Power Supply, I/O Module, Motor Drive
>
> มีการต่อกราวด์และติดตั้ง Surge Protection ตามจุดที่มีความเสี่ยง
>
> ใช้ Label ระบุชื่ออุปกรณ์และหมายเลขขั้วต่อเพื่อให้ง่ายต่อการตรวจสอบภายหลัง
>
> ออกแบบตู้ควบคุมให้มีระบบระบายอากาศ พร้อมการจัดสายไฟแนวตั้งและแนวนอนแยกกัน

นอกจากนี้ ยังควรออกแบบ ระบบไฟสำรอง (UPS) สำหรับ PLC ที่ต้องทำงานต่อเนื่อง เพื่อป้องกันข้อมูลสูญหายเมื่อไฟดับ

## 10.3 การบำรุงรักษา PLC

ระบบอัตโนมัติในโรงงานอุตสาหกรรมมีความซับซ้อนและทำงานต่อเนื่องตลอดเวลา โดยมี PLC (Programmable Logic Controller) เป็นหัวใจหลักในการควบคุมกระบวนการผลิต การบำรุงรักษา (Maintenance) จึงมีบทบาทสำคัญในการป้องกันการหยุดชะงักของระบบ และยืดอายุการใช้งานของอุปกรณ์ให้ทำงานได้อย่างเสถียร

ในอดีตการบำรุงรักษามักเกิดขึ้นเฉพาะเมื่อเครื่องจักรเสีย (Breakdown Maintenance) แต่ปัจจุบันแนวทางได้เปลี่ยนไปสู่การ บำรุงรักษาเชิงป้องกัน (Preventive Maintenance) และบำรุงรักษาเชิงคาดการณ์ (Predictive Maintenance) เพื่อคาดการณ์ความเสียหายล่วงหน้าและลดเวลาหยุดการผลิต การเข้าใจแนวคิดเหล่านี้จะช่วยให้ผู้เรียนสามารถวางแผน ตรวจสอบ และดูแลระบบ PLC ได้อย่างเป็นระบบและปลอดภัย

### 10.3.1 การบำรุงรักษาเชิงป้องกัน (Preventive Maintenance)

การบำรุงรักษาเชิงป้องกันคือการดำเนินการตรวจสอบและดูแลระบบตามรอบระยะเวลาที่กำหนดไว้ เพื่อป้องกันไม่ให้เกิดความเสียหายก่อนเวลาอันควร ตัวอย่างกิจกรรมสำคัญ เช่น

1.  ตรวจสอบแรงดันและกระแสไฟฟ้าในระบบจ่ายไฟของ PLC ให้คงที่อยู่ในช่วง ±10% ของค่ามาตรฐาน

2.  ตรวจสอบและทำความสะอาดพัดลมระบายอากาศ (Fan Filter Unit) เพื่อป้องกันความร้อนสะสมในตู้ควบคุม

3.  ตรวจสอบสภาพสายสัญญาณและขั้วต่อ (Terminal Block) ไม่ให้หลวม หรือเกิดคราบออกไซด์

4.  ตรวจสอบสัญญาณ Input/Output โดยใช้โปรแกรม GX Works3 Monitor เพื่อทดสอบการตอบสนองของอุปกรณ์

5.  สำรองข้อมูลโปรแกรม (Backup Program) ลงในคอมพิวเตอร์หรือ SD Card ทุกครั้งก่อนการอัปเดต

แนวทางนี้เน้นการทำงานตามตารางบำรุงรักษา เช่น รายวัน รายเดือน และรายปี เพื่อให้มั่นใจว่าทุกอุปกรณ์อยู่ในสภาพพร้อมใช้งานเสมอ

### 10.3.2 การบำรุงรักษาเชิงคาดการณ์ (Predictive Maintenance)

เป็นแนวทางบำรุงรักษาที่ใช้เทคโนโลยีช่วยวิเคราะห์ข้อมูล เช่น การวัดอุณหภูมิ, การสั่นสะเทือน, หรือจำนวนชั่วโมงการทำงานของ PLC เพื่อคาดการณ์ว่าอุปกรณ์จะเริ่มเสื่อมสภาพเมื่อใด

ตัวอย่างเทคนิคการบำรุงรักษาเชิงคาดการณ์ ได้แก่ การติดตั้งเซนเซอร์ตรวจวัดอุณหภูมิและความชื้นในตู้ควบคุม เพื่อส่งข้อมูลแบบเรียลไทม์เข้าสู่ระบบ IoT หรือ SCADA

### 10.3.3 ขั้นตอนการตรวจสอบและบำรุงรักษา PLC

> ขั้นตอนพื้นฐาน

1.  ปิดระบบไฟฟ้า (Power Off) ก่อนทำการตรวจสอบหรือทำความสะอาดทุกครั้ง

2.  ตรวจสอบสภาพตู้ควบคุมภายนอก ว่าปลอดฝุ่น ความชื้น และแมลง

3.  เปิดตู้และใช้แปรงขนอ่อนหรือเครื่องเป่าลม (Air Blower) ทำความสะอาดแผงวงจรและพัดลม

4.  ตรวจสอบสายกราวด์ ให้อยู่ในสภาพแน่นและไม่ขาด

5.  ตรวจสอบแบตเตอรี่สำรอง (Battery Backup) ของ CPU Module และเปลี่ยนตามรอบเวลา (โดยทั่วไปทุก 3 ปี)

6.  สำรองข้อมูลโปรแกรม (Backup) ผ่าน GX Works3 → PLC Parameter → Backup/Restore

7.  บันทึกข้อมูลการตรวจสอบลงในแบบฟอร์มการบำรุงรักษา (Maintenance Log Sheet)

|---------------------------|------------|----------------|--------------|------------------|

## บทสรุป

ระบบ PLC อาจทำงานผิดพลาดได้จากสาเหตุด้านไฟฟ้า การติดตั้ง โปรแกรม และสภาพแวดล้อม การตรวจสอบอย่างเป็นระบบช่วยให้พบสาเหตุได้รวดเร็ว การป้องกันความเสียหายทำได้โดยออกแบบการติดตั้งที่ปลอดภัย ควบคุมสภาพแวดล้อม และใช้อุปกรณ์ป้องกัน ส่วนการบำรุงรักษาเชิงป้องกันและเชิงคาดการณ์ช่วยยืดอายุการใช้งานและลดความเสียหายที่อาจเกิดขึ้น พร้อมบันทึกผลเป็นหลักฐานเพื่อวางแผนในระยะยาว

## แบบฝึกหัดท้ายหน่วยเรียน

**คำชี้แจง:** ให้นักศึกษาตอบคำถามต่อไปนี้โดยใช้ความรู้จากบทเรียน พร้อมยกตัวอย่างประกอบ หากสามารถอธิบายพร้อมวาดภาพวงจรหรือแผนผังการต่อสายได้จะได้รับคะแนนเพิ่ม

**1. อธิบายความสำคัญของการตรวจสอบและบำรุงรักษา PLC ในระบบควบคุมเครื่องจักรอัตโนมัติ ว่ามีผลต่อประสิทธิภาพของกระบวนการผลิตอย่างไร**

<details><summary>เฉลย</summary>

PLC เป็นหัวใจของระบบควบคุมอัตโนมัติ หากเกิดความเสียหายจะทำให้เครื่องจักรหยุดทำงาน (Downtime) ส่งผลโดยตรงต่อปริมาณการผลิตและต้นทุน การตรวจสอบและบำรุงรักษาอย่างสม่ำเสมอจึงช่วย:

\- ป้องกันการหยุดชะงักที่ไม่คาดคิดของสายการผลิต

\- ยืดอายุการใช้งานของอุปกรณ์ลดค่าใช้จ่ายการเปลี่ยนทดแทน

\- รักษาคุณภาพและความต่อเนื่องของผลิตภัณฑ์

\- เพิ่มความปลอดภัยแก่ผู้ปฏิบัติงานในโรงงาน

</details>

**2. จากเนื้อหาในบทเรียน จงอธิบายความแตกต่างระหว่าง การบำรุงรักษาเชิงป้องกัน (Preventive Maintenance) และการบำรุงรักษาเชิงคาดการณ์ (Predictive Maintenance) พร้อมยกตัวอย่างการใช้งานในโรงงานอุตสาหกรรม**

<details><summary>เฉลย</summary>

Preventive Maintenance (บำรุงรักษาเชิงป้องกัน): ดำเนินการตามรอบเวลาที่กำหนด เช่น รายเดือน ราย 3 เดือน โดยไม่ขึ้นกับสภาพอุปกรณ์ เช่น ทำความสะอาดพัดลม ตรวจแรงดันไฟ สำรองโปรแกรม

Predictive Maintenance (บำรุงรักษาเชิงคาดการณ์): ใช้เทคโนโลยีวิเคราะห์ข้อมูลสภาพอุปกรณ์จริง เช่น เซนเซอร์วัดอุณหภูมิ/ความสั่นสะเทือน ส่งข้อมูลเข้า IoT หรือ SCADA เพื่อคาดการณ์ความเสียหายก่อนเกิดขึ้นจริง

ตัวอย่าง: โรงงานผลิตชิ้นส่วนยานยนต์ใช้ Preventive ตรวจ Terminal Block ทุก 3 เดือน และใช้ Predictive นับรอบรีเลย์ผ่าน PLC Counter เพื่อวางแผนเปลี่ยนก่อนหมดอายุ

</details>

**3. อธิบายขั้นตอนการตรวจสอบและแก้ไขข้อผิดพลาดของระบบ PLC (Troubleshooting) ตั้งแต่การสังเกตอาการเสียไปจนถึงการบันทึกผลการซ่อมบำรุง**

<details><summary>เฉลย</summary>

1\. ระบุอาการเสีย (Symptom Identification): สังเกตไฟแสดงสถานะ เสียงเตือน หรืออาการผิดปกติ

2\. วิเคราะห์สาเหตุที่เป็นไปได้ (Possible Cause Analysis): เช่น สัญญาณไม่เข้า รีเลย์ไม่ทำงาน โปรแกรมหยุด

3\. ตรวจสอบจุดที่สงสัย (Test and Verify): ใช้ Multimeter หรือ GX Works3 Monitor ตรวจ I/O ที่เกี่ยวข้อง

4\. ดำเนินการแก้ไข (Corrective Action): เปลี่ยนหรือซ่อมส่วนที่เสีย เช่น Sensor สายไฟ หรือแก้ไข Ladder

5\. บันทึกผลการซ่อม (Maintenance Log): บันทึกเพื่อใช้เป็นข้อมูลสำหรับการบำรุงรักษาในอนาคต

</details>

**4. จากภาพการตรวจสอบสถานะการทำงานของ PLC ด้วย GX Works3 Monitor ให้อธิบายว่าการตรวจสอบสถานะ Input และ Output มีประโยชน์อย่างไรในการระบุจุดบกพร่องของระบบ**

<details><summary>เฉลย</summary>

GX Works3 Monitor แสดงสถานะ X (Input) และ Y (Output) แบบเรียลไทม์ ช่วยระบุจุดบกพร่องได้อย่างรวดเร็ว

\- ตรวจสอบว่า Sensor ส่งสัญญาณหรือไม่ (X-bit เปลี่ยนสถานะหรือไม่)

\- ตรวจสอบว่า Output (Relay/Actuator) ทำงานตามคำสั่งของโปรแกรมหรือไม่

\- ช่วยแยกแยะว่าปัญหาอยู่ที่ฮาร์ดแวร์ (สายขาด Sensor เสีย) หรือซอฟต์แวร์ (Logic Error)

\- ลดเวลาในการ Troubleshoot เพราะเห็นข้อมูลทั้งระบบพร้อมกัน

</details>

**5. ยกตัวอย่างสาเหตุของความผิดพลาด (Error Cause) ของระบบ PLC อย่างน้อย 3 กรณี พร้อมอธิบายแนวทางการตรวจสอบและการแก้ไขที่เหมาะสม**

<details><summary>เฉลย</summary>

กรณีที่ 1 สายไฟขาดหรือหลวม → ตรวจสอบสายสัญญาณด้วย Multimeter ขันแน่น Terminal Block ทุกจุด

กรณีที่ 2 Sensor เสียหายหรือส่งสัญญาณผิดพลาด → ตรวจสอบสถานะ Input ด้วย Monitor ทดแทน Sensor ใหม่

กรณีที่ 3 Logic Error ในโปรแกรม Ladder → ใช้ Simulation Mode ทดสอบโปรแกรม ตรวจสอบลำดับตรรกะ และแก้ไข Rung ที่ผิด

กรณีที่ 4 สัญญาณรบกวน Noise จากมอเตอร์ → ใช้ Shield Cable เดินสายสัญญาณแยกจากสายไฟแรงดันสูง ติดตั้ง Ferrite Core

</details>

**6. อธิบายหลักการป้องกันความเสียหายของ PLC ที่เกิดจากไฟกระชาก ความร้อน และสัญญาณรบกวนทางไฟฟ้า พร้อมระบุอุปกรณ์ที่ใช้ในการป้องกันแต่ละกรณี**

<details><summary>เฉลย</summary>

ไฟกระชาก (Surge) ติดตั้ง Surge Protector (SPD)/Varistor (MOV) ที่แหล่งจ่ายไฟ ใช้ Opto-isolator แยกวงจร แยกสายไฟโหลดกำลังสูงออกจากสายสัญญาณควบคุม

ความร้อน (Heat: ติดตั้ง PLC ในตู้ควบคุมที่มีพัดลม Fan Filter Unit เว้นช่องว่างระบายความร้อนอย่างน้อย 50 mm รอบ PLC หลีกเลี่ยงติดตั้งใกล้หม้อแปลง

สัญญาณรบกวน (Noise) ใช้ Shield Cable สำหรับสาย Sensor ใช้ Ferrite Core ในสายมอเตอร์/โซลินอยด์ เดินสายสัญญาณแยกจากสายไฟแรงดันสูงอย่างน้อย 10 ซม.

</details>

**7. จากตาราง 'ปัจจัยแวดล้อมและแนวทางการปรับปรุง' ให้นักศึกษาวิเคราะห์ปัจจัยใดที่มีผลกระทบต่อการเสื่อมสภาพของ PLC มากที่สุด พร้อมเสนอแนวทางการปรับปรุงที่สามารถนำไปใช้ได้จริง**

<details><summary>เฉลย</summary>

จากตารางปัจจัยแวดล้อม ปัจจัยที่มีผลกระทบมากที่สุดคือ อุณหภูมิสูง และ สัญญาณรบกวนทางไฟฟ้า เนื่องจาก

\- อุณหภูมิสูงทำให้วงจรอิเล็กทรอนิกส์เสื่อมสภาพเร็วกว่าอายุการใช้งานที่ออกแบบ ทำให้ต้นทุนการเปลี่ยนทดแทนสูง

\- สัญญาณรบกวนทำให้ PLC รีเซ็ตกะทันหัน อาจเกิดความเสียหายต่อกระบวนการผลิตและความปลอดภัย

แนวทางปรับปรุง

\- ติดตั้ง Air Conditioner ควบคุมอุณหภูมิตู้ควบคุมให้ไม่เกิน 40°C

\- ใช้ Shield Cable ทุกเส้นและติดตั้ง Noise Filter สำหรับวงจรมอเตอร์

</details>

**8. อธิบายขั้นตอนการบำรุงรักษาเชิงป้องกัน (Preventive Maintenance) ของ PLC อย่างน้อย 5 ขั้นตอน พร้อมระบุเครื่องมือที่ใช้ในแต่ละขั้นตอน**

<details><summary>เฉลย</summary>

ขั้นตอนที่ 1 ตรวจสอบแรงดันและกระแสไฟฟ้าในระบบจ่ายไฟ ให้คงที่ ±10% ด้วย Multimeter (รายเดือน)

ขั้นตอนที่ 2 ตรวจสอบและทำความสะอาดพัดลมระบายอากาศ (Fan Filter Unit) ด้วยแปรงและลมเป่า (รายเดือน)

ขั้นตอนที่ 3 ตรวจสอบสภาพสายสัญญาณและขันแน่น Terminal Block ด้วยไขควงทดสอบ (ราย 3 เดือน)

ขั้นตอนที่ 4 สำรองข้อมูลโปรแกรม (Backup .gxw) ผ่าน GX Works3 ลงคอมพิวเตอร์หรือ SD Card (ราย 6 เดือน)

ขั้นตอนที่ 5 ตรวจสอบและเปลี่ยนแบตเตอรี่สำรอง CPU Module ด้วยการสังเกต Error Alarm (ราย 3 ปี)

ขั้นตอนที่ 6 บันทึกผลการตรวจสอบทุกรายการลงใน Maintenance Log Sheet เพื่อการวางแผนในอนาคต

</details>

**9. อธิบายประโยชน์ของการจัดทำบันทึกหรือแบบฟอร์มการบำรุงรักษา (Maintenance Log Sheet) ว่าช่วยเพิ่มประสิทธิภาพในการดูแลระบบ PLC อย่างไร**

<details><summary>เฉลย</summary>

Maintenance Log Sheet ช่วยเพิ่มประสิทธิภาพการดูแลระบบ PLC ในด้านต่าง ๆ ดังนี้:

\- ติดตามประวัติการซ่อมบำรุงและการเปลี่ยนอะไหล่ ทำให้ทราบรูปแบบการเสียซ้ำ

\- ใช้เป็นฐานข้อมูลวางแผนการซื้ออะไหล่สำรองล่วงหน้า ลดการหยุดรอชิ้นส่วน

\- ช่วยให้วิศวกรใหม่เข้าใจประวัติระบบได้รวดเร็วเมื่อต้องซ่อมบำรุง

\- ใช้เป็นหลักฐานประกอบการตัดสินใจอัปเกรดหรือเปลี่ยน PLC

\- สนับสนุนมาตรฐาน ISO และระบบ TPM (Total Productive Maintenance) ขององค์กร

</details>

**10. ให้นักศึกษาวาดหรืออธิบายผังการบำรุงรักษา PLC ในโรงงานอุตสาหกรรม โดยเชื่อมโยงกระบวนการตั้งแต่การตรวจสอบ การป้องกัน ไปจนถึงการซ่อมบำรุง พร้อมอธิบายบทบาทของวิศวกรควบคุมในกระบวนการนี้**

<details><summary>เฉลย</summary>

ผังกระบวนการบำรุงรักษา PLC

\[ตรวจสอบประจำ\] → \[ประเมินสภาพ\] → \[พบปัญหา/ปกติ\] → \[แก้ไข/บำรุงรักษา\] → \[ทดสอบ\] → \[บันทึก\] → \[วางแผนรอบถัดไป\]

รายละเอียด

\- ตรวจสอบประจำ ตรวจ Indicator Lamp แรงดันไฟ พัดลม ขั้วต่อตามตาราง Preventive Maintenance

\- ประเมินสภาพ ใช้ GX Works3 Monitor ดูสถานะ I/O และ Error Log

\- แก้ไขเมื่อพบปัญหา ตามขั้นตอน Systematic Troubleshooting 5 ขั้นตอน

\- บทบาทวิศวกรควบคุม กำหนดตารางบำรุงรักษา วิเคราะห์ Error Code อัปเดตโปรแกรม สำรองข้อมูล จัดทำรายงาน และวางแผนป้องกันระยะยาว

</details>
